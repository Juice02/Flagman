FlagMan: feature flags with per-environment rollouts and targeting rules

Without feature flags, deploying code and releasing a feature happen at the same moment. If the feature breaks, the only fix is another deploy, and every user gets every change at once.

With a flag, code ships switched off. A dashboard decides who gets the feature and when, and the app asks FlagMan at runtime, so turning a feature on or off never needs a deploy.

Turn off a broken feature without a deploy.

Switching the flag off changes the answer the app gets on its next /evaluate call, and users fall back to the existing checkout.

The dashboard and the app are separate.

The app asks POST /evaluate; FlagMan answers from the current config for that environment.

Release to some users first.

Each user has a fixed bucket, CRC32(flagKey:userId) % 100. At 50%, buckets 0–49 get the feature, and a user's answer never changes at random.
